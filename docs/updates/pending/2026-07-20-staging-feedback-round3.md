## Thread/topic: staging-feedback-round3

**Sections likely affected:** 3, 6, 9

**Customer-facing:**
The might/power badge mask is now a smaller, tighter circle (the previous round's version read as oversized), the correct-answer mascot celebration sticks around about a second longer, the end-of-session screen is back to one centered block of text instead of being spread across the whole screen, and study batches now draw a different, shuffled set of cards each time instead of the same cards in the same order every session.

**Team-facing:**
Five items from Ashwin's third round of staging feedback on [PR #55](https://github.com/Shwinsta-ra/riftacademy/pull/55) (merged to `integration`), in `fix/staging-feedback-round3` (branched off latest `integration`).

1. **Might/power circle re-measured and shrunk, twice.** Round 2 sized the circular might mask to fully inscribe the WHOLE printed badge (banner shape, icon + digit), which Ashwin reported as too big on both mobile and desktop, for both the top-right (Unit/Champion/Legend) and bottom-right (Gear/Equipment) positions. Re-measured from real card pixels (downloaded via `curl`, analyzed with Python/Pillow) what actually needs hiding: just the printed digit(s), not the shield icon next to it (constant across every card, never reveals the might value). First pass sized the circle tightly around a single basic Unit's digit (~100px diameter) -- but a second measurement pass on a Champion card (Volibear) found its digit rendered noticeably larger (~74px tall/wide vs ~36px on a basic Unit), and a similar spread showed up across Gear rarities (Long Sword vs the Epic Skyfall of Areion). The first tight-fit size would have clipped the edge of a Champion's digit, an actual leak risk. Final sizing uses the worst-case (largest) measured digit across templates plus a real safety margin -- still meaningfully smaller than round 2's full-badge circle (~19% card width vs ~25%), but with confirmed full coverage (verified via a 2.2x on-page zoom, not just percentages on paper) rather than the tightest theoretically-possible fit. `quizPositions.json`'s `might.default`/`might.Gear` updated accordingly.
2. **Sparklet (the correct-answer mascot) celebration extended ~1s.** The overlay's fade-in/hold/fade-out sequence went from ~900ms total to ~1900ms (the mid-sequence `Animated.delay` bumped from 560ms to 1560ms). The "Correct!" toast's own animation duration was bumped to match (900ms to 1900ms) so it doesn't fade out early and leave the mascot sitting there unlabeled for the extra second. The hop/cap-nod/spark flourish animations themselves were left at their original speed (they're a quick one-time flourish that settles into a resting pose, not something that needed to play in slow motion) -- only the overall on-screen hold time changed.
3. **Session-complete screen reverted to one centered block.** Round 2's redesign spread the headline/countdown/tip/button across three independent zones at fixed percentages down the full screen height; Ashwin asked for it back as a single vertically-centered column (same `styles.centered` pattern used elsewhere in this screen), keeping the specific line breakdown from round 2 (headline, then the "unlocks in:"/countdown pair, then the tip, then the button) but with the countdown label and tip text sized up slightly (14px to 16px, 13px to 15px) per the new spec.
4. **Study batches now shuffle instead of always drawing the same cards in the same order.** Root cause: `buildBatch()` in `leitner.ts` sorts each category pool (missed/new/review) by `(box, dueAt)`, and every never-seen card ties on both (box 1, dueAt 0 by convention) -- since `Array.sort` is stable, that tie always resolved back to `allCardIds`'s own array order, so a fresh account (or anyone whose "new" pool dominates a filter, like someone testing only the Vendetta set) got the exact same N cards in the exact same order every single batch. Fixed by shuffling each pool BEFORE the stable sort (a standard "randomize sort ties" technique): genuine priority differences (lower box, earlier due time) still win regardless of shuffle order, so the missed-cards-first / most-overdue-first scheduling logic is completely unaffected -- only ties (overwhelmingly the "new" pool) now resolve randomly. Verified live: cleared local progress twice in a row and confirmed the first card drawn was a different card art each time.

**Anything another thread working today should know before touching related code:**
`quizPositions.json`'s `might` regions are now digit-only (plus margin), not full-badge coverage -- if you're re-measuring any mask region from real card art, check MULTIPLE templates/rarities of that card type before finalizing a size, not just one; font/badge size can vary meaningfully across templates within the same "type" (a Champion's stat digits render noticeably larger than a basic Unit's, even though both use the `might.default` position). `leitner.ts` now has its own local `shuffle()` helper (same Fisher-Yates as `attributeQuiz.ts`'s, kept separate rather than factored into a shared util for a 6-line function) -- if you add a new pool-based sort elsewhere in the scheduling logic, shuffle before sorting, not after, or ties will silently go back to array order.
