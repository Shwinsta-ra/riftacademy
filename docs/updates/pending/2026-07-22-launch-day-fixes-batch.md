## Thread/topic: launch-day-fixes-batch

**Sections likely affected:** 2, 3, 9

**Customer-facing:**
Filters no longer reset to default if the app reloads during the 10-minute study-batch cooldown. The cooldown countdown no longer briefly flashes a wrong number on load. Text-effect quiz questions always show exactly 4 answer options (one card was showing 6). The Domains filter now shows the 6 real domains plus Colorless instead of 15+ combo chips, and picking one domain now correctly includes dual-domain cards that contain it. "Reset progress" now shows a real confirmation popup before it does anything (it silently did nothing before) and is a solid red button. "What's this card's Power cost?" questions no longer leak the answer through the size of the hidden box. Several card texts with a missing space after a period (e.g. "Kill a gear.[Flow (4)(R)]") are fixed.

**Team-facing:**
Eight items from the 2026-07-22 launch-day handoff, all on one branch/PR per Ashwin's updated call (including the filters/cooldown item, which is no longer a solo hotfix):

1. **Filters reset after cooldown** — confirmed `FiltersProvider` (`filtersStore.tsx`) never persisted anything; it's now backed by the same settings-table/localStorage pattern as the batch gate (`getSavedFilters`/`setSavedFilters` in `db.native.ts`/`db.web.ts`), loaded once on mount and saved on every `setFilters` call. Verified live in a browser: set a domain filter, hard-reload the page, the chip is still selected and `localStorage.riftboundTrainerQuizFilters` survives the reload.
2. **Countdown flash** — `QuizScreen`'s `nowTick` was seeded once at mount (before the async `loadSession` chain resolves) and only updated once the gate's own 1s interval fired, so the first countdown render used a stale, too-large value until it self-corrected a second later. Fixed by stamping `nowTick` to the same `now` used to compute `batchGateUntil`, in the same synchronous branch. Verified live: first paint and one second later show a monotonic decrement, no jump.
3. **6 answers instead of 4** — root cause was `buildBracketSwapQuestion` (Group B Bucket 1, shipped last night): it builds up to 5 distractors (1 target-false-variant + 2 comparison cards x 2) and never sampled down, unlike every other question mode. Now samples 3 of the generated pool, same pattern as the hand-authored-variant path. A pre-existing test (`attributeQuiz.test.ts`) had literally asserted the buggy 6-option/5-distractor behavior as correct — updated it to assert the sampled-to-4 behavior, and added a blanket `options.length <= 4` check to the Group B smoke test so this class of regression fails loudly next time. Verified live across 20 real quiz questions in a browser session — every single one rendered 3 or 4 options, never more.
   - **Legend name-testing removal: confirmed already shipped**, not stale. `bca7492` (last night) already excludes "name" mode for `type === "Legend"` in both `eligibleModes`'s auto-computed set and its override-immunity check. ven-147-166 (Shen, Eye of Twilight)'s control-sheet "Name" row is inert dead data — `buildAttributeQuestion` can never route to "name" mode for a Legend regardless of what's in `quizQuestions.json`, since mode selection only ever picks from `eligibleModes`'s output.
4. **Domain filter showing combo chips** — `getAvailableDomains()` was deriving distinct values straight off `card.domain`, which stores a dual-domain card's value as one combined string ("Fury/Chaos") rather than two entries — surfacing 15+ chips. Now returns the fixed 7-item list sourced from `theme.ts`'s `DOMAIN_COLORS` keys (so it can't drift out of sync with the domain color tokens). Filter matching (`getFilteredCards`) now splits each card's domain string on "/" and checks for component overlap with the selected domains (OR logic across multiple selections), replacing the old exact-string-equality check. New `src/lib/__tests__/quiz.test.ts` covers both. Verified live: Settings screen now shows exactly Fury/Calm/Mind/Body/Chaos/Order/Colorless.
5. **Reset progress does nothing** — confirmed the hypothesis: it used React Native's `Alert.alert()`, which has no real implementation on react-native-web (this is a web deploy). Replaced with the existing `AppModal` component (added an optional `ctaDestructive` prop that swaps its CTA to `theme.incorrect` red instead of the default accent — first modal in the app that needed a destructive-styled CTA). The trigger button on the Stats/Progress screen is now solid filled red instead of an outline. Verified live: tap opens a real modal with an explicit confirm step; confirming clears progress and closes the modal; the button reads as a clear destructive action now.
6. **Power-cost mask leak** — `powerCost` already had its own position-config key (separated from `energyCost` back in PR #67), but its height still scaled with the card's own true `power` value via a per-card formula — which is itself a leak (a taller box visibly means a higher power, same bug class as the original mismatched-region issue). `power` is now a fixed rect like every other mode, sized to the worst case (4 pips) and extended up to also cover the energy-cost circle above it, computed from Ashwin's existing measured intercept/slope values at their maximum rather than guessed from scratch. **Could not visually tune this against real card art in this session** — this sandboxed environment's network policy blocks `cmsassets.rgpub.io` outright (confirmed via the proxy's own status endpoint), so the exact pixel dimensions in `quizPositions.json`'s `power.default`/`power.Gear` are a principled extrapolation, not eyeballed against a render. Flagging for a real visual pass (a session with image access, or Ashwin directly) before treating the numbers as final. Added `attributeQuiz.test.ts` coverage proving the region is now identical across a 1-power and a 4-power card (and a 1-power vs 2-power Gear card).
7. **Missing spaces after periods** — regex sweep (`\.` immediately followed by an uppercase letter or `[`, insert a space) across every card's `text`/`flavour` field in `cards.json`. Found and fixed 39 cards (38 VEN, 1 UNL flavour line), not just the 21 spot-checked last night — the broader sweep catches cases beyond what was hand-checked. Re-scanned afterward: 0 remaining matches. **Important implementation note for future JSON edits to this file:** don't reserialize `cards.json` with plain `JSON.stringify` — the file is fully ASCII-escaped (`\uXXXX`, no raw UTF-8 bytes, Python `ensure_ascii=True` convention) and `JSON.stringify` silently un-escapes existing `\uXXXX` sequences into raw UTF-8 on every field it touches, not just the ones you're editing, which showed up as unrelated diff noise on two unrelated cards' curly-quote/accented flavour text the first time through. Had to write a custom ASCII-safe serializer to keep the diff to exactly the 39 intended lines.
   - **Flagging back to Ashwin**, per the handoff: the Master Card Inventory itself needs the same period-spacing cleanup, or this regresses the next time `merge_sheet.py` runs against the sheet as source of truth. Separately noticed `apply_vendetta_images.py` writes `cards.json` with `ensure_ascii=False` (inconsistent with the rest of the pipeline's all-ASCII convention) — not touched this session since it's not part of today's batch, but worth a look if unicode diff noise shows up after a future Vendetta image backfill run.
8. **Battlefield rendering (Mystic Vortex, Piltovan Forge)** — investigated thoroughly, could not reproduce or fix with confidence. Findings: no rotation/transform/duplicate-render logic exists anywhere in the client code (`QuizScreen.tsx`, `QuizCardArt.tsx`, `api/img.ts`) — grepped the whole codebase for it. Every Battlefield card, old (OGN/SFD/UNL) and new (Vendetta, including both flagged cards), uses the identical `BATTLEFIELD_ASPECT_RATIO` landscape path with no per-card special-casing, and that path was already explicitly fixed and verified working against a real Battlefield card in PR from July 19 (`355d1f9`). All 59 Battlefield cards' `imageUrl` filenames uniformly indicate a landscape (`-1039x744`/`-1038x744`) asset, including both flagged cards, so this isn't a new-Vendetta-specific layout difference either. No duplicate `imageUrl` values across different cards (ruling out an image mix-up from the ingestion script). **Could not go further**: this sandbox's network policy blocks `cmsassets.rgpub.io` entirely (confirmed both via direct `curl`/proxy status and via `WebFetch`, both returning connection-rejected/403), so I could not fetch or view either card's actual rendered art to check whether the source asset itself is malformed. Given the specificity of "rotated 180 degrees" and "renders twice" in the description and the total absence of any code-level mechanism that could cause either, my best-supported hypothesis is a source-asset quality issue at the Riftcodex CDN for these two specific images rather than an app bug — but this is not confirmed. **Recommend**: re-check these two cards live in the app (not via a re-shared screenshot) to confirm still-reproducible, and if so, hand off to a session with image/network access so the actual pixels can be inspected before guessing at a client-side fix that could risk the 57 other battlefields that already render correctly.

**Anything another thread working today should know:**
- `AppModal` gained an optional `ctaDestructive` prop (solid `theme.incorrect` red CTA) — use this instead of a one-off style override if another destructive confirmation is needed.
- `getMaskRegions("powerCost", card)` no longer takes a dynamic-formula path; `quizPositions.json`'s `power` key is now a plain fixed-rect table exactly like `cost`/`might`/`name`/`text`, so anything reading that JSON file directly (not through `getMaskRegions`) needs to expect the new shape.
- `getFilteredCards`'s domain matching is now component-based (splits on "/"), not exact-string — if you're adding a new filter dimension with a similar multi-value-per-field shape, this is the pattern to copy.
