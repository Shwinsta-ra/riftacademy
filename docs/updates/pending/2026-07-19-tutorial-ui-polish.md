## Thread/topic: tutorial-ui-polish

**Sections likely affected:** 3, 6, 9

**Customer-facing:**
Fixed a handful of rough edges from tonight's staging feedback: the correct-answer mascot no longer overlaps the caption or answer options (including on battlefield cards, which are shaped differently from the rest), the quiz card art dropped its gold trim in favor of a softer ambient glow, the "What's new" section title reads cleaner, the legal notice at the bottom of Home scrolls normally again instead of staying pinned in place, and the boxes that hide the answer on quiz cards are now shaped and sized to the actual card element they're covering (a circular badge over the cost pip, tight rounded badges over the might/power number) instead of generic oversized rectangles.

**Team-facing:**
Nine fixes from tonight's live staging feedback on the onboarding tutorial and Rune Glow visual work, in `fix/tutorial-visual-polish` (branched off `integration` post both PR #46 and PR #49, since PR #46 had already merged by the time this session started).

1. **Tutorial highlight architecture change (done first, per the handoff spec).** `TutorialCallout` no longer draws a separately-measured ring overlay; each screen that owns a tutorial target (`HomeScreen`'s "Set filters"/"Review Cards", `SettingsScreen`'s newest-set chip/"Set filters" CTA) now applies a conditional border directly to its own style, active only when `useTutorial().currentStep?.id` matches. This removes an entire class of "ring doesn't match the button's actual bounds" bugs by construction, and incidentally fixed the reported mobile positioning bug (verified separately, not just assumed): the ring used to extend well past the target on a scrolled-down page. One thing this surfaced that wasn't in the spec: the highlight color had to move from `theme.accent` to `theme.text` (near-white), since the "Review Cards" `GlowButton` and the "Set filters" CTA (once dirty) are already filled with `theme.accent`, so an accent-colored border on top would have been invisible.
2. **Sparklet repositioning, revised twice.** First pass moved it from centered-over-the-whole-screen (landed bottom-center of the card) to `top: 70%` of the card's own box, right side, peeking past the edge. `QuizCardArt` gained an optional `decoration` prop, rendered on its unclipped outer container, so Sparklet can anchor to the card specifically. **Second pass (per Ashwin):** `top: 70%`-of-container-height silently assumed every card is a tall portrait box. Battlefield cards render in a landscape container (see item 7), which is much shorter: the same percentage anchor pushed Sparklet well past the bottom of a battlefield card, hanging in empty space below it. Switched to fixed pixel offsets from the bottom-right corner (`bottom: -8, right: -10`) instead of a percentage of height, so it pins to the actual corner regardless of the container's aspect ratio. Verified on both a portrait card and a Battlefield card.
3. **Card border rendering artifact, then the whole foil-rim treatment dropped (per Ashwin).** Root cause of the original artifact: `QuizCardArt`'s trim SVG used a hardcoded `viewBox="0 0 100 140"` that didn't exactly match the real card aspect ratio, and `preserveAspectRatio="none"` stretched that mismatch into a visibly elliptical corner against the `clip` View's perfectly circular CSS `borderRadius`. That got fixed, but the bigger question raised alongside it (keep the on-top rim vs. drop it for a glow-behind treatment) has now been decided: **dropped.** `QuizCardArt` no longer renders the gold rim, base gradient, or holographic sheen/trim SVGs at all, just the card image in a plain rounded clip, with `GLOW.cardRing`'s ambient shadow (already rendering behind/around the view, not on top) doing the whole treatment. `FOIL` removed from `theme.ts` (nothing references it anymore); `RIFT_BRAND`'s widened-gold-use comment updated to drop the now-gone foil-rim exception, leaving only the Sparklet cap tassel.
4. **Legal footer un-pinned.** Reverted the earlier fixed-footer change; the LJJ notice is back to being the last item inside `HomeScreen`'s `ScrollView` instead of a sibling that stays pinned to the bottom of the screen.
5. **No em dashes, going forward.** New standing rule: no em dashes in any app-facing text (prompts, labels, tutorial copy, alerts, changelog entries) or in any document produced for this project (specs, PM doc entries, fragments, commit messages). Fixed every instance found in shipped app copy: `QuizScreen`'s pacing-gate and empty-pool messages, `SettingsScreen`'s deck-filter helper text, all six CSV export/share `Alert.alert` messages and the match invariant warning in `MatchDetailScreen`, the five discard/recycle action labels (both player columns), the "What's new" section title, and all three tutorial step strings in `tutorialSteps.ts`. Left one line alone on purpose: `SettingsScreen.tsx`'s `deck.name.indexOf(" — ")` parses an em dash that lives in imported deck-list data (not authored copy), and the dash itself never reaches the rendered UI since `splitDeckName` strips it out.
6. **"Skip tutorial" italicized**, landed as part of the item 3 rewrite.
7. **Fixed a portrait-only assumption in `QuizScreen`'s card sizing (per Ashwin's review).** `CARD_ASPECT_RATIO` (744/1039, portrait) was applied to every card regardless of type, so Battlefield cards -- the same physical template rotated 90 degrees, measured at 1038x744 -- were force-fit into a tall portrait container via `resizeMode="contain"`, letterboxed top and bottom with the foil base-gradient filling the gap. Added `BATTLEFIELD_ASPECT_RATIO = 1039/744` (the exact inverse) and pick the right one per card's `type`, so the container always matches the card's real shape and `resizeMode` can just be `"cover"` for everyone. Side effect worth flagging: this also fixes an apparent pre-existing mask-alignment issue for Battlefield quiz questions -- the position data in `quizPositions.json` is authored as percentages of the card's own rendered bounds, which only lined up correctly once the container stopped letterboxing (verified precisely via DOM measurement: mask regions now land at exactly the configured 30%/64% offsets against the image's actual rect).

8. **Quiz answer-mask zones redesigned to fit the real card elements (per Ashwin's follow-up feedback), and a real answer-leak bug found and fixed along the way.** The old masks in `quizPositions.json` were generic quadrant-sized rectangles (e.g. cost was a `0,0` box covering the whole top-left 20%x25% of the card) that visibly overlapped surrounding art. Measured the actual printed positions directly from real card art (downloaded via `curl` to sidestep the CDN's CORS restrictions, analyzed pixel-by-pixel with Python/Pillow) across Unit, Gear, Equipment, Champion, and Legend cards, and replaced the cost and might/power zones with tightly-fitted coordinates: cost stays top-left but shrinks to the pip's real footprint, might/power stays top-right for Units/Champions/Legends and moves to a new bottom-right zone for Gear/Equipment (matching where the badge is actually printed on that template). Name and text zones were already well-fitted from earlier work and are unchanged. The cost pip specifically renders as a true circle on the card art, so its mask now uses `borderRadius: 999`; the JSON width/height percentages are pre-calibrated to that circle at the portrait aspect ratio, so no runtime aspect-ratio math is needed (cost/power questions only ever occur on portrait-oriented cards). While live-testing the resized might mask on "Brazen Buccaneer," caught a real bug: the initial redesign used a semi-transparent fill (`rgba(15,15,22,0.92)`) for a softer look, and the underlying might value was visibly readable through/beside the "?" placeholder, defeating the mask's purpose. Confirmed via DOM measurement and a second pixel-measurement pass that the mask's position was correct (not a placement bug) and that the transparency itself was the cause. Fixed by making the mask fill fully opaque (`#0f0f16`); retested and confirmed no leak. `maskOverlay` and the new `maskOverlayCircle` variant are shared styles in `QuizScreen.tsx`, so this fix and the shape work apply identically regardless of card type or mask position.

**New standing rule or convention worth capturing:**
No em dashes anywhere in app-facing text or in any document produced for this project, effective tonight (July 19). See item 5 above.

**Anything another thread working today should know before touching related code:**
`QuizCardArt` now takes an optional `decoration` prop for anything that needs to anchor to the card's own box and bleed past its edge (used by Sparklet) -- prefer that over adding another screen-level absolutely positioned overlay, and anchor with fixed offsets from a corner/edge, not a percentage of height, since card containers can be portrait OR landscape (see item 7). The foil-rim-versus-glow-behind question from item 3 is now resolved (glow-behind won) -- `QuizCardArt` no longer imports `FOIL` from `theme.ts` at all, and that export has been removed. Any other Rune Glow component still using a hardcoded/approximated viewBox or a percentage-of-container-height anchor is worth a second look given what caused both item 2 and item 3's original bugs.
