## Thread/topic: staging-feedback-round2

**Sections likely affected:** 3, 6, 9

**Customer-facing:**
A batch of polish fixes from the second round of staging feedback on the onboarding tutorial and RiftRecall quiz: the tutorial bubble no longer covers the "Set Filters" button, the quiz question now sits right under the card instead of floating in a big gap, question titles no longer strand a single word on their own line, the might/power badge mask is now a circular badge matching the cost mask, fill-in-the-blank questions read the card's actual text in normal (not all-bold, bracketed) style, the feedback form is quicker to fill out (no required "what happened" field, single-line answer boxes, relabeled "Submit feedback" button), and the end-of-session "Back to Home" screen has a cleaner, more deliberate layout with an updated tip line.

**Team-facing:**
Seven items from Ashwin's staging pass on PR #52 (already merged to `integration`), in `fix/staging-feedback-round2` (branched off latest `integration`, which already includes PR #52's mask redesign work).

1. **Tutorial tooltip race condition (root cause of the box-covers-the-button bug).** `SettingsScreen`'s auto-scroll-to-reveal effect (`scrollToEnd` on the newest-set-chip tap) and `useTutorialTarget`'s own re-measure effect (triggered by the same tap advancing the step to `setFiltersCTA`) were both scheduled via `requestAnimationFrame` in the same render cycle -- a race that let the tutorial bubble's `measureInWindow` call capture the button's PRE-scroll on-screen position, so the bubble rendered pinned to where the button used to be, not where it landed after scrolling. Fixed by explicitly re-measuring `setFiltersCTATarget` ~400ms after kicking off the scroll (long enough for the scroll animation to settle); harmless no-op via `registerTarget`'s own step-id check if some other step happens to be active when it fires. Also updated the step's copy to "Tap Set Filters to lock in your choice." (capitalized to match the button label style).
2. **Quiz question spacing.** `QuizScreen`'s `scrollContent` had `justifyContent: "space-between"` on a `flexGrow: 1` container, which stretched the gap between the card and the question text to fill any leftover viewport height on a short question. Removed it -- the card and question now stack naturally with just the `prompt` style's existing 16px `marginTop` as the gap.
3. **Orphan-word line wrapping.** Added `preventOrphanWord()` in `textDisplay.ts`, which joins a string's last two words with a non-breaking space (` `) so a wrapped line never stray a single word onto its own line. Applied to `question.prompt` in `QuizScreen`. Caught a real web-only gotcha while verifying: react-native-web's default Text styling sets `overflow-wrap: break-word`, which lets the browser break INSIDE an NBSP-joined pair when it doesn't fit a line, silently defeating the whole trick. Fixed with a web-only `wordBreak: "keep-all"` override on `styles.prompt` (`Platform.OS === "web"` gated; native has no such default and needs no override). Verified via DOM inspection that the NBSP character is present, and via screenshot that the line wrap now lands two words on the last line.
4. **Might/power masks made circular to match the cost mask.** Extended `isCircularMask` in `QuizScreen` to include `"might"` mode (previously only `energyCost`/`powerCost`). The real printed might/power badge is actually a rounded rectangle, not a circle, but per Ashwin's explicit call this is a deliberate style choice (visual consistency over exactly tracing the underlying art). Recalculated `quizPositions.json`'s `might.default` and `might.Gear` regions to render as true circles (same width%/height% aspect-ratio-corrected technique used for the cost pip): `default` keeps its original top edge (anchored to the badge's real top-right corner) and grows the height downward to make the box square in rendered pixels; `Gear` keeps its original bottom edge (anchored to the card's bottom-right corner, where that badge sits) and grows upward. Both directions were chosen specifically so the box only ever grows, never shrinks, relative to the previously-fitted (already leak-free) rectangle -- can't reintroduce an answer leak by construction. Live-verified the top-right (default) case; the Gear/Equipment bottom-right case is unverified through the live UI (see note below) but shares the identical rendering path and was derived with the same anchor-preserving math.
5. **Fill-in-the-blank question formatting -- fixed in the data file, not code.** Ashwin asked whether to fix this in code or in `quizQuestions.json`; went with the data file. Reason: `QuizScreen` already renders `question.prompt` (bold, large) and `question.caption` (dim, italic, subtext) as two separate styled elements, and the auto-generated `buildFillBlankQuestion()` in `attributeQuiz.ts` already does exactly the right split (`prompt: "Fill in the blanks:"`, `caption: <card text with blanks>`). The bug was that all 66 hand-authored `fillBlank` variants in `quizQuestions.json` had the entire prompt-plus-bracketed-card-text baked into one `prompt` string, bypassing that split entirely. Ran a one-time script to split each: `prompt` becomes the fixed `"Fill in the blanks:"`, and a new `caption` field gets the bracket-wrapped card text with the OUTER bracket pair stripped (any inner keyword tags like `[Action]`/`[Legion]` are real card-text markup and were left alone). 65 of 66 entries matched the expected `Fill in the blanks:  [...]` pattern and converted cleanly; one entry (`unl-196-219`) didn't match the pattern at all (missing prefix, and using a 20-underscore blank instead of `____`) and was left untouched as a separate, pre-existing data-quality issue outside this fix's scope.
6. **Feedback sheet trimmed down.** In `FeedbackSheet.tsx`: `canSend` no longer requires non-empty `happened` text (only a tag selection is required now), and the "(required)" label was removed from "What happened?" to match. Both `TextInput`s (`happened`/`expected`) switched from `multiline` with a 64px `minHeight` to a fixed 44px single-line height (`height: 44`, no `textAlignVertical`). Shortened the first box's placeholder to "Mask covered the wrong card element." so it visibly fits on one line. Bumped the submit button's `marginTop` from 22 to 32 for more separation from the inputs above, and relabeled it from "Send report" to "Submit feedback".
7. **Session-complete cooldown screen redesigned.** The `batchGateUntil` render block in `QuizScreen` (shown after finishing a batch, with the countdown to the next unlock) no longer uses one centered text block. Now three independently absolutely-positioned zones spanning the screen height (same percentage-of-container pattern as the quiz mask regions): headline ("Nice work on that set!") at `top: 10%`, a countdown block (small "Your next batch of cards unlocks in:" label + large mm:ss value) at `top: 42%`, and a bottom block (tip text + "Back to home" button) at `top: 70%`, landing the button roughly 75% down the screen with the tip line just above it. Tip copy updated to "Short breaks between sets improves your card recall". Verified at both mobile (390px) and desktop (1440px) widths -- the percentage-based zones scale cleanly at both.

**Anything another thread working today should know before touching related code:**
`quizQuestions.json`'s `fillBlank` entries now have a `caption` field alongside `prompt` (previously prompt-only) -- if you're hand-authoring a new fill-in-the-blank override, follow that shape (`prompt: "Fill in the blanks:"`, `caption: <text with blanks, no outer brackets>`), not the old single-string style. `QuizScreen.tsx`'s `isCircularMask` now covers three modes (`energyCost`, `powerCost`, `might`) -- if a new circular-badge mask type gets added, extend that list rather than introducing a second boolean. The `preventOrphanWord()` helper in `textDisplay.ts` is web-affected by RNW's default `overflow-wrap: break-word`; if you apply it to a new Text element, you likely also need the same `Platform.OS === "web"` `wordBreak: "keep-all"` override alongside it, or the NBSP trick silently does nothing on web while still working natively.
