**New standing rule or convention worth capturing:**

**Printed-reference style — now the house standard for this project.** Ashwin adopted it explicitly on 2026-07-25 after the v8 pass. Full rules go in `CLAUDE.md`; the short version is nine rules:

1. **Say it once, in the place it's used.** Cross-reference by page number rather than repeating a target. A steps section is a sequence and a box to write the time in — not a summary of the detail printed below it.
2. **Generate from the source of truth.** Card tables come from `cards.json` or the inventory CSV via script. Hand-typed tables drift.
3. **Encode, don't describe.** `1O`, `2PP`, `(A)`, `(R)`, `†`, tier digits 1–4. One legend line, then symbols.
4. **One job per page, and fill it.** Below ~85% fill the page is carrying too little and should absorb something or be merged.
5. **Blank space, never underscores.** Left-justify everything. Underscores fight handwriting; centred columns break the scan.
6. **Instructions must not contradict the form.** "Mark C or A, don't write" sat directly above a write-in column and had to be rewritten.
7. **PDF for anything printed.** Google Docs formatting is not reliable enough to specify against.
8. **Verify by measuring, not by assuming.** Page count, fill percentage, and right-margin overflow are all checkable programmatically. A long card name silently overhung the page edge and only measurement caught it.
9. **Let the visual design carry the meaning.** Colour-coded headers, column position, and a single digit beat four labelled subsections.
