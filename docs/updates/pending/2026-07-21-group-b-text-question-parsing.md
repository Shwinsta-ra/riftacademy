## Thread/topic: group-b-text-question-parsing

**Sections likely affected:** 3 (feature tracker — RiftRecall/quiz-engine row), 9 (log)

**Customer-facing:**
The quiz now asks a sharper, more specific question for almost every card instead of falling back to "pick the real text out of a lineup" so often. Cards with exactly one number in their effect text now get a single-blank fill-in-the-blank (previously only cards with exactly two numbers got this treatment); cards with 3+ numbers get a fill-in-the-blank on whichever number matters most (Might > damage > draw > cost); cards with no numbers but a real keyword or speed tag (e.g. "[Reaction]", "[Ganking]") now get a "which is the real text" question built from swapped-tag false variants instead of unrelated cards' text.

**Team-facing:**
Implemented all four Group B buckets from `docs/handoffs/riftcoach-thread-handoff.md`'s sibling spec (the text-parsing handoff, not the match-analyzer one — see `~/Downloads/group-b-text-parsing-handoff.md`, not committed to the repo), in `src/lib/attributeQuiz.ts`:
- **Bucket 3 (1 number)** and **Bucket 4 (3+ numbers)** both reuse the existing `fillBlank` mode — `buildFillBlankQuestion` now branches on blank count (1 / 2-unchanged / 3+) instead of only handling exactly 2. Distractors reuse `pickNearbyDistinctNumbers` (sequential, non-negative), with a new rule excluding `0` as a distractor (never as the real answer) when the number's verb context makes `0` a nonsensical no-op — "deal 0 damage," "draw 0 cards," etc.
- **`classifyKind`** — the Group A baseline-generation script's verb-context classifier was never committed to the repo (confirmed via full git history search), so it's rebuilt from scratch here, exported from `attributeQuiz.ts`. It scans ~40 chars before a number for governing verbs (deal/draw/discard/recycle/might/cost), with two forward-looking exceptions confirmed against real card text: Might is often phrased number-first ("+2 Might"), and activation-cost notation ("(1), [Tap]:") has no preceding verb at all.
- **Bucket 4's priority order** (Might > damage > draw > cost, first-in-text-order tiebreak) lives in `pickBlankForMultiple`.
- **Bucket 2 (0 numbers, no bracket)** — `buildTextQuestion`'s fallback pool now has a same-domain+type+subtype tier ahead of the existing same-set+type/type-only/whole-pool chain, still widening progressively if that tier is too small.
- **Bucket 1 (0 numbers, has a permutable bracket)** — new `bracketSwap` mode + `buildBracketSwapQuestion`. Pulls 2 comparison cards from the same domain+type+subtype pool, builds each card's "permuted-false" variant (Action<->Reaction swap, or a different domain-derived keyword swapped into a curated keyword bracket), assembles the target's real text as correct + 5 distractors (target-false + 2×comparison-real + 2×comparison-false) — a 6-option question, not the usual 4. Reuses the shipped `keyword` mode's `extractFirstKeyword` regex to distinguish a real keyword bracket from incidental cost/param notation (e.g. `[Assault 2]`, `[Accelerate (1)(R)]` are never permutation targets).
- **Routing nuance worth knowing:** the handoff's bucket sizes (measured on raw "has brackets" text shape) don't exactly match `bracketSwap`'s real eligible count, because a 0-number card whose only bracket is incidental (e.g. only `[Equip (R)]`, no real keyword or speed tag) has nothing meaningful to permute — those fall through to Bucket 2's `text` mode instead. Confirmed via full-pool count: 361 cards have 0 blankable numbers; 162 have a real permutable bracket (`bracketSwap`), the other 199 fall to `text`.
- QuizScreen.tsx: `bracketSwap` mode added to the same long-answer `maxLines: 6` treatment as `text` mode (its options are full sentences, not short stat values). The options grid layout was already option-count-driven (not mode-driven), so the new 6-option case needed no layout changes.

**New standing rule or convention worth capturing:**
`classifyKind` and the Group A baseline-generation script's outputs are genuinely gone from version control — anyone who needs that script's other logic in the future should check with Ashwin for local/scratch copies rather than assuming it's recoverable from git history.

**Testing:**
Added `src/lib/__tests__/attributeQuiz.test.ts` — 12 targeted cases matching the handoff's testing checklist (one real card per verb context for Bucket 3, the Might-vs-cost priority case for Bucket 4, domain/type/subtype fallback verification for Bucket 2, the exact Star-Crossed 5-distractor re-verification plus a keyword-bracket spot check for Bucket 1, and a Group A regression check), plus a full-pool smoke test (879 cases) that builds a question for every real card currently eligible for `fillBlank`/`bracketSwap`/`text` and asserts no crashes, valid `correctIndex`, and no duplicate option strings. `npm run test` (921 tests) and `npm run typecheck` both pass clean.

**Anything another thread working today should know before touching related code:**
`attributeQuiz.ts` now exports `classifyKind`, `buildFillBlankQuestion`, `buildTextQuestion`, and `buildBracketSwapQuestion` (previously all module-private) purely for test access — no other behavior change from that.
