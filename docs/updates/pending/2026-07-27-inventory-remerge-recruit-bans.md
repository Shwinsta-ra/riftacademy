## Thread/topic: inventory-remerge-recruit-bans

**Sections likely affected:** 2, 3, 6, 9

**Customer-facing:**
Master card data refreshed across the board (928 cards total, up from 918) — Vendetta text/keyword/shorthand corrections, Recruit tokens now display as "Recruit, DE/NX/ZN", and a new hand-authored fill-in-the-blank question for Forgotten Relic. Cards banned in 1v1 (e.g. Draven, Vanquisher) no longer surface in RiftRecall's Review Cards, but stay in the app's total card count.

**Team-facing:**
Two behavior changes in `scripts/merge_sheet.py`, both driven by real bugs found while running this merge:
- **1v1-banned cards are no longer deleted from `cards.json`.** They're flagged `banned1v1: true` instead (new field on `Card` in `types.ts`), and `getFilteredCards` in `quiz.ts` excludes them from quiz eligibility — same pattern as the existing `imageUrl === null` / `isToken` exclusions. Previously, a card that was both brand-new AND 1v1-banned in the same sheet run (Draven, Vanquisher) got inserted then deleted in the same script run, so its verified errata text could never render anywhere. Ashwin's explicit correction: the master dataset must never lose cards this way.
- **Card `name` is now refreshed from the sheet for every matched card**, not just champions/legends. Previously the Recruit token rename (`Recruit (DE)` → `Recruit, DE`) was silently skipped entirely — not just the name, every field on the row — because `normalize_name()`'s mismatch guard stripped the old parenthetical suffix down to bare `"recruit"`, read the sheet's comma-format name as an unrelated card, and bailed out of the whole row update. `normalize_name()` now converts trailing `"(X)"` into `", X"` (matching the existing "Name, Epithet" convention) instead of stripping it.
- **Found and fixed a third, unrelated bug while regression-testing:** the sheet's `Domain(s)` column now writes dual-domain cards comma-separated (`"Fury, Body"`) rather than the old combined-string convention. The generic `parse_list()` was splitting that into two separate array elements instead of the single `"Fury/Body"`-joined element `cardMatchesDomainFilter` expects — this silently broke domain-filter matching for all 100 dual-domain cards in the dataset (not just Vendetta). Added a dedicated `parse_domain()` that joins multiple values with `/` instead of leaving them as separate list entries. Caught by `src/lib/__tests__/quiz.test.ts`'s domain-filter tests, which is why the pipeline is worth full-suite-testing after a merge, not just spot-checking the cards named in a handoff spec.

**New standing rule or convention worth capturing:**
1v1 competitive bans are now a quiz-eligibility concern (`quiz.ts`), not a dataset-membership concern (`merge_sheet.py`). Any future feature that needs "is this card tournament-legal" should read `card.banned1v1` directly rather than assuming banned cards are simply absent from `cards.json`.

**Anything another thread working today should know before touching related code:**
- `scripts/merge_sheet.py`'s `CATEGORY_MAP`-adjacent script, `scripts/apply_master_sheet.py`, also picked up a small fix today: its `CATEGORY_MAP` now accepts both singular `"fill in the blank"` and plural `"fill in the blanks"` sheet Category values (the sheet has both in the wild).
- One known, unresolved oddity (flagged to Ashwin, not fixed): `ven-112-166` (Zed, Without a Sound)'s Card Text formats its Action cost as `[Action] (1)(P):` in the master sheet, rather than the `[Action (1)(P)]:` convention used everywhere else — this makes the quiz generator treat it as a 2-number fill-blank (`"0 | 1"`) instead of the intended single-number Might question (`"0"`). `src/lib/__tests__/attributeQuiz.test.ts` documents the expected single-blank behavior and currently fails against the live sheet content pending Ashwin's call on the card text.
